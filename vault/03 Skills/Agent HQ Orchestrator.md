# Agent HQ Orchestrator

## When to use

Use for a multi-file feature, a task needing specialist review, anything that touches Studio and code, work that needs visual concepts, or queued work that must survive the current chat.

## Procedure

1. Identify whether this is a manual owner request or a scheduled run. Let Agent HQ's lane gate decide whether to run.
2. Read the active project rules, the role's brief, relevant system note, and the supplied acceptance criteria.
3. Give each role only files it owns. Never run two writers on the same files or two Studio-driving tasks at once.
4. Use the existing role split: Lead scopes; Architect plans; Builder implements server/shared code; UI implements approved UI; World builds map space; Librarian audits assets; Economy/Merchant own values; Designer and Thumbnail artist use Antigravity; Reviewer, Playtester, and Kid tester verify; Producer records decisions.
5. Return a concise report through HQ. Record at most two reusable lessons when a real lesson was learned.
6. Let Agent HQ create quality gates. A FAIL returns to the same role with concrete feedback. After the configured retries, raise an owner decision instead of looping forever.

## Boundaries

- Do not run a second swarm, plan-exec, or parallel role team inside an active Agent HQ task.
- Antigravity creates concepts/art only. Claude Code owns implementation, tests, documentation, and Studio MCP.
- Agents do not publish, spend Robux, install software, change a live place, or enable unattended schedules.
- Owner-only output appears under Needs you: design selection, asset/licence decisions, manual Studio action, final approval, publishing, prices, and credentials.
